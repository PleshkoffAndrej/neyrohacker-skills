# Режим 3: ШИФРОВКА — ТЗ по идее

Шифровка — это .md-файл, который принимающая сторона (другой скилл или сам пользователь в любом ИИ) превращает в контент без единого уточняющего вопроса.

Запускай когда пользователь выбрал идею: «сделай ТЗ по идее №3», «разверни вторую», «беру первую».

## Принцип

Шифровка отвечает на всё, что спросил бы автор: о чём, для кого, каким тоном, откуда факты, чем цеплять, чем заканчивать, что проверить. Если после чтения шифровки остаются вопросы — она собрана плохо.

**В шифровке нет готового контента.** Ни абзаца будущего поста, ни текста слайдов. Хуки и CTA — исключение: это заготовки-варианты, из которых автор выбирает, и они помечены как варианты.

## Что собрать перед записью

1. Идею из сводки со всеми цитатами-опорами.
2. Профиль ниши: аудитория, тон, стоп-темы.
3. Первоисточники — перечитай их, если в сводке остались только обрывки. Скупая шифровка бесполезна.
4. Тип контента и обоснование из `content-types.md`.

## Шаблон

Файл: `Разведка/шифровки/<slug>.md`

```markdown
# Шифровка: <заголовок идеи>

**Дата:** <дата> · **Ниша:** <ниша> · **Оценка:** <N>/100

## Задача

**Тип контента:** <тип>
**Почему этот тип:** <одна строка обоснования>
**Альтернатива:** <второй подходящий тип, если есть>
**Не подходит:** <тип и почему — экономит автору попытку>

## Аудитория и тон

**Для кого:** <из profile.md, одной строкой>
**Что читатель должен унести:** <одна конкретная мысль или приём>
**Тон:** <из profile.md>
**Стоп-темы:** <чего не касаться>

## Суть идеи

<2–4 строки: какой угол берём и почему он не банален>

## Сырьё

Материал из источников. Цитаты дословные — на них опирается автор.

### Источник 1 — <название>, <ссылка>
> <цитата 1>
> <цитата 2>

**Что отсюда берём:** <одна строка>

### Источник 2 — ...

## Факты, требующие проверки

Утверждения, которые пойдут в текст и могут устареть или оказаться неточными.
Проверку делает принимающая сторона — резидент только помечает.

- <утверждение> — источник: <ссылка>, дата: <когда сказано>
- <цифра> — проверить актуальность

## Заготовки хуков

Варианты первой строки, разные механики. Выбрать один, не склеивать.

1. <цифра/конкретика>
2. <контр-интуиция>
3. <вопрос-боль>
4. <называние врага>
5. <личный опыт>

## Заготовки CTA

1. <сохранить>
2. <перейти>
3. <ответить в комментариях>

## Структура

<Скелет под выбранный тип: секции из content-types.md с одной строкой,
что в каждой должно оказаться. Именно скелет, а не написанный текст.>

## Что НЕ делать

- <ловушка темы: например «не превращать в обзор инструмента — угол про воркфлоу»>
- Не выдумывать цифры сверх тех, что в сырье
- Не ссылаться на источник как на авторитет без имени

## Рекомендация по передаче

<Если в сессии есть подходящий скилл — «→ передай в `имя-скилла`».
Если нет — «Тип контента: <тип>. Открой любой ИИ и работай по этой шифровке».>
```

## После записи

- Помечай идею в `ledger.md` статусом `в работе`.
- В чат выведи путь к файлу и три строки: тип контента, для кого, главная мысль. Не пересказывай шифровку целиком — она затем и файл.
- Если в сессии есть подходящий скилл — предложи запустить его прямо сейчас: «Открыть в <скилл>?» Не запускай без ответа.

## Проверка перед выдачей

```
[ ] Все цитаты дословные, у каждой есть ссылка
[ ] Ни одного абзаца готового контента (кроме помеченных заготовок)
[ ] Тип контента обоснован, названа альтернатива
[ ] Сомнительные факты вынесены отдельным блоком
[ ] Структура — скелет, а не текст
[ ] Читается человеком, который не видел сводку
```
