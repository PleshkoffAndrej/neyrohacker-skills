# Режим 5: АВТОЗАПУСК

Сводка ценна, когда лежит на столе до того, как пользователь сел работать. Автозапуск делает это без него.

## Как создать

Используй инструменты scheduled tasks (create_trigger). НЕ используй локальный планировщик — задача, созданная им, умрёт вместе с сессией и пользователь молча останется без сводок.

Каждое срабатывание запускает **новую сессию без памяти об этом разговоре**, поэтому промпт задачи должен быть самодостаточным:

```
Собери сводку идей по нише <ниша>. Рабочая папка: <абсолютный путь к папке Разведка>.
Прочитай profile.md, sources.md, ledger.md, rejected.md этой ниши,
собери материал за последние <N> дней, выдай сводку по своей процедуре,
запиши файл в Разведка/сводки/ и обнови ledger.md.
Ниша уже настроена — вопросов не задавай, работай на том, что в профиле.
```

Последняя строка обязательна: в фоновом запуске спросить некого, а без неё скилл уйдёт в ВЕРБОВКУ и вернёт пустоту.

## Расписание

Спроси у пользователя время и дни, предложи разумное по умолчанию:

| Тип ниши | Предложение | Почему |
|----------|-------------|--------|
| Быстрая повестка (ИИ, крипта, новости) | будни, 7:00 | к открытию ноутбука сводка готова, за сутки набирается материал |
| Недельные циклы (право, тендеры, B2B) | понедельник, 8:00 | повестка меняется неделями, ежедневный сбор даст повторы |
| Вечнозелёная тема | пятница, 10:00 | планирование контента на следующую неделю |

Ниш несколько — заводи отдельную задачу на каждую, вразнобой по времени. Три сводки одновременно в 7:00 никто не прочитает.

Глубина сбора должна совпадать с частотой: ежедневный запуск — 1–2 дня, недельный — 7–8 дней. Иначе журнал будет отсекать 80% улова как повторы, и сводка придёт пустой.

## Поведение при автозапуске

В фоновом запуске действуют отличия:

- **Не задавай вопросов** — ответить некому. Ниша не настроена или источники недоступны — запиши сводку с пометкой о проблеме и закончи.
- **Не спрашивай «что мимо?»** — этот вопрос задаётся только в живом диалоге. Обратную связь соберёшь при следующем ручном запуске.
- **Улов пустой** — не выдумывай идеи, чтобы заполнить файл. Запиши честно: сколько источников прочитано, почему пусто. Пустая честная сводка полезнее десяти выдуманных идей.
- **Порог для автосводки выше** — выноси в топ только идеи от 60 баллов. Пользователь читает её мельком, слабое отвлекает.

## Проверка задачи

После создания покажи пользователю: время, дни, нишу, куда пишется файл. Скажи, что первая сводка придёт тогда-то. Если он захочет проверить сразу — запусти задачу вручную (fire_trigger), а не пересобирай руками: так проверяется именно то, что будет работать по расписанию.

## Остановка и правка

- Пауза — отключением задачи, не удалением: история запусков сохранится.
- Меняется расписание — правь задачу, не создавай вторую. Две задачи на одну нишу дадут дубли в журнале.
- Ниша закрыта — удали задачу, папку ниши оставь. Журнал ещё пригодится.
