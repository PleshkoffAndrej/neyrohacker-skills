# Режим 1: ВЕРБОВКА — настройка ниши

Ниша — это профиль, под который резидент фильтрует эфир. Без неё сбор даёт «интересное вообще» вместо «интересное тебе».

Запускай режим когда: ниш нет вообще, пользователь просит завести новую, добавить источники или поправить профиль.

## Процедура

Веди интервью **по одному вопросу за раз**. Не вываливай анкету списком — пользователь бросит на третьем пункте. После каждого ответа записывай и переходи дальше.

### Шаг 1. Имя ниши

«Как назовём нишу? Одно слово латиницей для папки — например `neyroseti`, `tendery`.»

Создай `Разведка/ниши/<ниша>/`.

### Шаг 2. Пять вопросов профиля

Задавай по одному:

1. **Кто аудитория?** Не «все» — конкретно: кто эти люди, чем занимаются, какой у них уровень.
2. **Зачем они тебя читают?** Что уносят с собой: приём, инструмент, ориентир в шуме, эмоция.
3. **Какой тон?** Дай выбрать: экспертный, дерзкий, дружелюбный, с юмором, вдохновляющий, сухой-практичный.
4. **Какие рубрики?** Постоянные форматы, которые уже есть или хочется: разбор инструмента, кейс, промпт дня, новость с мнением.
5. **О чём НЕ пишем?** Стоп-темы. Самый недооценённый вопрос — он режет половину мусора на входе.

### Шаг 3. Источники

Спроси: «Дай 5–10 источников, которые реально читаешь — телеграм-каналы, сайты, YouTube-каналы.»

Затем предложи добор: по нише подбери 8–12 кандидатов и покажи списком с пометкой, чем каждый полезен. Пользователь вычёркивает лишнее. Для ниши «нейросети» стартовый набор — в `assets/seed-ai.md`.

Проверь каждый источник на доступность (см. `istochniki.md`) — мёртвый источник в списке хуже, чем его отсутствие, потому что каждый сбор будет спотыкаться. Недоступные помечай `[?]` и скажи об этом.

### Шаг 4. Запись

Запиши два файла по шаблонам ниже, создай пустые `ledger.md` и `rejected.md`. Покажи пользователю, что получилось, одним экраном.

## Шаблон profile.md

```markdown
# Ниша: <название>

## Аудитория
<кто, чем занимается, уровень>

## Зачем читают
<что уносят с собой>

## Тон
<один из: экспертный / дерзкий / дружелюбный / с юмором / вдохновляющий / сухой-практичный>

## Рубрики
- <рубрика 1>
- <рубрика 2>

## Стоп-темы
- <о чём не пишем>

## Приоритет тем
<что поднимать в топ сводки: например «практика важнее новостей»>

## История правок
| Дата | Что изменилось | Откуда узнали |
|------|----------------|---------------|
```

## Шаблон sources.md

```markdown
# Источники ниши <название>

| # | Источник | Тип | Как читаем | Приоритет | Статус |
|---|----------|-----|-----------|-----------|--------|
| 1 | @prompterskaya | telegram | t.me/s/prompterskaya | высокий | ок |
| 2 | Хабр, хаб ИИ | сайт | habr.com/ru/hubs/artificial_intelligence | средний | ок |
| 3 | <канал> | youtube | youtube.com/feeds/videos.xml?channel_id=<id> | средний | ок |

## Веб-разведка
Постоянные запросы для WebSearch, если источников мало или нужна свежесть:
- <запрос 1>
- <запрос 2>
```

Приоритет влияет на скоринг: идея из источника высокого приоритета получает +5 к оценке. Так профиль пользователя постепенно перевешивает случайный шум.

## Дообучение ниши

Ниша не настраивается один раз. Правь её на каждой сводке — это то, что превращает шаблон в личный инструмент.

**После выдачи сводки спроси одной строкой:** «Что мимо?» Пользователь называет номера — запиши их в `rejected.md` с причиной и внеси правку в `profile.md` (обычно в «Стоп-темы» или «Приоритет тем»). Каждую правку фиксируй в «Истории правок» с указанием, из какого отказа она выросла.

Не спрашивай больше одного уточнения за сводку. Резидент не допрашивает Центр.

## Формат rejected.md

```markdown
| Дата | Идея | Причина отказа |
|------|------|----------------|
| 2026-09-06 | Обзор новой модели X | Новости без практики — не наш формат |
```

Перед следующим сбором читай этот файл: идеи, похожие на отклонённые, получают −20 к оценке и в топ не идут.
